# handbook/ —— 代码里放不下的设计说明

本目录收**「有用、但放在代码里会淹掉代码」**的内容：环境变量清单、事故复盘、
跨模块的链路约定、历史迁移缘由。**代码里只留一句「为什么」+ 一个指到这里的指针**，
不再维护第二份长说明。

`AGENTS.md` 仍是项目约定的唯一入口（目录结构、命令、关键约定）；
本目录是它的补充：AGENTS.md 要保持可扫读，写不进表格的细节放这里。

业务域 `apps/docs/`（文档转换与 Dify 推送）是**功能**，与本目录无关，别混。

`design/` 子目录收**设计提案与决策记录**：域分层、assets/configs 拆分方案、core 外部连接实例。
拆分方案与域分层已落地，保留作决策记录；外部连接仍是部分落地。现状仍以本目录根部的
「已实现行为」文档为准——细节与各文档状态见 [`design/README.md`](design/README.md)。

## 注释规范（什么时候写注释、什么时候写文档）

口诀：**代码只留简单说明，解释进本目录**。代码文件与 `.env` / `envs/*.env` 一样适用。

留在代码里的：

- **一句话说明这段在做什么、怎么用**；
- **函数 / 类的参数与返回值**：类型、单位、边界、返回形态（例如「单条命中给 `dict`，多条给 `list`」）、
  是否有副作用或写库，一两行说清；
- **非显然的「为什么」但必须就近才不出错**：顺序依赖、防重入、绕开某个第三方行为——一句话，
  详细推演放进本目录并在代码里留一行指针。

进本目录的：

- 清单型内容（环境变量、字段映射、阈值表）；
- 原理与推演（某个第三方行为为什么这样、某个阈值怎么来的、跨库差异）；
- 复盘与历史（某次事故、某次迁移为什么这么拆）；
- 跨文件链路（从 A 模块调到 B 模块再落到 C 表）；
- 会被反复引用的设计论证（`AGENTS.md` 里已有结论时，这里只写细节）。

要删的：分隔横线、`django-admin` 模板残留、复述下一行代码的注释、
注释掉的死代码、只剩「历史注记」价值又没有当前约束的句子、被本次改动作废的旧说明。
