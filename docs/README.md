# docs/ —— 代码里放不下的设计说明

本目录收**「有用、但放在代码里会淹掉代码」**的内容：环境变量清单、事故复盘、
跨模块的链路约定、历史迁移缘由。**代码里只留一句「为什么」+ 一个指到这里的指针**，
不再维护第二份长说明。

`AGENTS.md` 仍是项目约定的唯一入口（目录结构、命令、关键约定）；
本目录是它的补充：AGENTS.md 要保持可扫读，写不进表格的细节放这里。

业务域 `apps/docs/`（文档转换与 Dify 推送）是**功能**，与本目录无关，别混。

## 注释规范（什么时候写注释、什么时候写文档）

留在代码里的：

- **非显然的「为什么」**：顺序依赖、防重入、绕开某个第三方行为、阈值取值的直觉；
- **契约边界**：函数/类的输入输出约定、单位、幂等性、谁能写这张表；
- 一行能说清、读代码时**正好需要**的信息（放得离代码近才有人看）。

进本目录的：

- 清单型内容（环境变量、字段映射、阈值表）；
- 复盘与历史（某次事故、某次迁移为什么这么拆）；
- 跨文件链路（从 A 模块调到 B 模块再落到 C 表）；
- 会被反复引用的设计论证（`AGENTS.md` 里已有结论时，这里只写细节）。

要删的：分隔横线、`django-admin` 模板残留、复述下一行代码的注释、
注释掉的死代码、只剩「历史注记」价值又没有当前约束的句子。
